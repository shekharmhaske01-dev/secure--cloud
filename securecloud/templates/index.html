The storage pipeline

  1. 1
    UploadStaged to disk with a server-side size limit.
  2. 2
    SegmentSplit into independent blocks (a partial final block is fine).
  3. 3
    EncryptFresh nonce + AAD binding each block to its file and index.
  4. 4
    StoreOne cloud object per encrypted block, named with an opaque id.
  5. 5
    ReconstructFetch, authenticate, decrypt and reassemble in block order.

How your file is protected

  • A unique 256-bit data-encryption key is generated for every file.
  • Blocks are sealed with AES-256-GCM; the tag is verified before any plaintext is released.
  • Additional authenticated data binds each block to the format version, the file identifier and the block index — so blocks cannot be moved between files or reordered.
  • The file key itself is wrapped by a key-encryption key that lives only in the environment, never in the database.
  • Only encrypted blocks and metadata are stored; plaintext never leaves the application server.
