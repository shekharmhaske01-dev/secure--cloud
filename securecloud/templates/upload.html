Preparing…

Uploads are rate limited. Each block is encrypted with a fresh nonce before it leaves this server.

What happens on upload

  1. The file is written to a staging directory with a server-enforced size limit.
  2. A random 256-bit data-encryption key (DEK) is generated for this file only.
  3. The file is split into {{ human_size(block_size) }} blocks.
  4. Each block is encrypted with AES-256-GCM using a fresh nonce and AAD v1|file-id|block-index.
  5. Each encrypted block is uploaded as its own object, named with an opaque identifier — never your filename.
  6. All objects are verified, then the DEK is wrapped with the key-encryption key and only the wrapped key is stored in the database.
  7. If anything fails, the metadata row is marked failed, the uploaded objects are removed, and any leftover objects are queued for retry.
